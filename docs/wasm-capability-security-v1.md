# WASM capability security contract v1

This is the normative host-boundary contract for every plugin language and runtime. Kinetix owns enforcement. This repository owns the WIT surface, package permission vocabulary, and portable adversarial fixtures. A runtime cannot claim conformance merely because the plugin SDK or fixture smoke test passes.

## Authority and approval

Effective authority is the intersection of the signed package's declarations, explicit host approval, the selected WIT world, and invocation context. Limits are the minimum of package requests and host ceilings. Installation, publisher trust, catalog metadata, `provides`, and possession of an import or credential reference do not grant authority. Unknown permissions are invalid under the [manifest schema](../schemas/plugin-manifest-v1.schema.json); unknown authority-bearing imports must fail linking. Missing approval means denial. Updates that expand permissions need new approval; revocation applies to subsequent calls and invalidates outstanding credential handles.

The host binds each invocation to a verified plugin identity, tenant/account context, and approved capability set. Guest-supplied IDs cannot switch that context. Denial happens before secret resolution, DNS/transport, or mutation. WIT calls return a redacted `permission_denied` or limit error where their signature allows it; otherwise they trap, return no data, or discard logging. No fallback to native APIs, permissive WASI, or partial unauthorized side effects is allowed. Error strings are not a stable test oracle; authority and side effects are.

The v1 manifest has only `network_hosts`, `credential_scopes`, and `credential_read` permissions. Storage is requested through `limits.storage`. Log and clock declarations are their WIT imports, approved as part of the selected world's installation policy, and independently revocable by the host. There are no filesystem, process, environment, socket, randomness, or system-keychain grants in this vocabulary. Do not invent extra manifest fields to enable them.

## Capability inventory

| Capability | Authority and approval | Required bounds |
| --- | --- | --- |
| `host-http.send` | Buffered control-plane HTTP to hosts both declared in `network_hosts` and approved; invocation must permit control-plane I/O. Adapters do not acquire inference transport authority. | `max_outbound_requests` per invocation, request and response `max_http_body` bytes, remaining wall time; see HTTP rules below. |
| `host-credential.lease` and HTTP credential references | Approved `credential_scopes` plus invocation-authorized account; references and handles are designators, not grants. | Handles bound to plugin, tenant, scope, account, lifetime and revocation; recheck on every use. No secret bytes in guest-visible results. |
| `host-credential.read` and any secret-bearing guest input/result | Both declared and separately approved `credential_read = true`, approved scope and invocation account. Approval UI must label plaintext access high risk. | Only the selected credential, within invocation memory/time limits. Never expose the host credential store. |
| Legacy `host-credential.sign` | Scope/account/egress checks as above. Returning a secret-bearing header additionally requires plaintext approval. | Prefer credential injection inside `host-http`; returning a bearer header is not opaque use. |
| `host-storage.get/put/delete` | Plugin-private KV in a host-bound tenant/plugin namespace; positive storage request plus approval for access. Host-provided read-only configuration is not arbitrary storage access. | Approved value-byte quota across all keys; bounded key bytes and entry count; atomic quota checks, including concurrent writes. |
| `host-storage.cache-set` | Only a core-invoked cached routing-fact refresh; not a general persistence or scheduling grant. | At most 256 facts, names at most 128 ASCII bytes, valid JSON, positive TTL at most 24 hours, total values within storage quota. Commit snapshot only after successful refresh. |
| `host-log.log` / telemetry | Only plugin-namespaced diagnostic output through approved logging policy; no guest-selected sink, path, or metric labels with secret data. | Finite per-record and per-invocation byte budgets, redaction before persistence/export; see telemetry rules below. |
| `host-clock` | Approved world import, read-only Unix seconds/milliseconds. API-v3 adapters instead receive core-supplied time in reserved context. | Invocation call/time budget. No timers, sleeps, scheduling, or additional WASI clock imports. |
| Randomness | No current WIT import or v1 permission. Core supplies OAuth state/PKCE inputs; no ambient entropy access. | Any future random capability needs a versioned contract, explicit approval and finite byte budget before introduction. |

All invocations also have finite memory, wall-time and execution-fuel ceilings. Zero authority budgets confer no authority; zero resource requests must never mean unlimited execution. Hosts may reject unusable limits or apply stricter ceilings. Type-only WIT dependencies convey no authority. API-v1/v2 host-import signatures remain unchanged; API-v3 adapters remain import-free. A multi-world component does not inherit authority from its other exports.

## HTTP and credential egress

- Require HTTPS, no URL userinfo, no IP literals, and default port 443. Parse and normalize hosts (lowercase, IDNA, trailing-dot normalization) before comparison. Exact declarations match exact hosts. `*.example.com` matches only subdomains with a DNS label boundary, never the apex or `example.com.attacker`.
- Validate every destination, including provider URLs returned by adapters and every redirect. Disable redirects or reauthorize each hop. A redirect cannot expand authority or forward credentials outside their approved egress hosts.
- Host-mediated resolution/connection must block loopback, private, link-local, multicast, unspecified and metadata-service addresses, including IPv4-mapped IPv6. Validate all resolved addresses and pin validated destinations through connection establishment to prevent DNS rebinding. Any future private-network exception needs a separate contract and approval, not a wildcard bypass.
- Count each actual outbound attempt, including redirects, against the invocation budget. Reject an oversized request before sending. Bound response buffering, marking truncated bodies with `body-truncated = true`; do not present truncated content as complete. Deadlines cover resolution, connections, body reads and redirects.
- Credential egress is the intersection of network permission and host-owned credential/provider egress policy. A second approved network host does not authorize sending it the first provider's credential. Reject caller-controlled auth overrides that could expose host credentials. Never return injected headers or secrets in responses, error evidence, traces or request dumps.

A lease is an opaque identifier, not an encoded secret or a transferable token. Do not infer a consumable lease protocol from its string representation: the current HTTP WIT uses `credential-ref`, and unsupported named references fail closed. Forged, stale, revoked, cross-plugin, cross-tenant or wrong-account references must not resolve.

**Legacy exposure:** the WIT comment on `sign` says secrets never cross, but its returned `http-request` can contain bearer headers. Likewise adapter `apply-auth` accepts a credential string. These signatures alone cannot guarantee secrecy. Hosts claiming this contract must deny secret-returning `sign` without plaintext approval, or return only a non-secret representation; any adapter given plaintext needs that same approval. No ABI change is made here. Existing host implementations need enforcement tests before claiming conformance.

Plaintext grants permit a malicious guest to copy a secret into its linear memory or an approved request body. Reliable zeroization and prevention of arbitrary encoding/covert-channel exfiltration cannot be promised. Keep plaintext exposure exceptional, confine its egress, and never persist memory dumps.

## Storage and telemetry

KV keys are data, never filesystem paths or namespace selectors. Namespace derives from verified host identity, not a guest parameter. Quota counts all stored value bytes; separately bound UTF-8 key size and entry count to prevent metadata exhaustion. Replacing a value releases its previous allocation atomically. Failed writes leave the previous state unchanged. Deletes cannot affect another plugin or host-owned `_config:` / `_cache:` state. Hosts may reject malformed keys; they cannot interpret traversal keys as host paths. Core observations, credentials and system credential stores are not plugin KV.

The portable test profile uses 256-byte keys, 1024 entries, 1024-byte log records and 4096 log bytes per invocation. Production hosts must publish finite ceilings and may lower them. Quota errors, telemetry, traps and client-facing plugin failures must redact known host credentials, auth headers, token fields, sensitive query parameters and body dumps before any sink. Prefer structured allowlisted evidence to logging arbitrary provider data. Redaction applies even when plaintext access was approved and when the guest returns an error rather than calling `host-log`. Bound diagnostic output before processing it; oversized logs may be truncated or dropped, never emitted unbounded. Redaction is defense in depth, not a confidentiality guarantee against a guest granted plaintext.

## Consumer conformance

[`wit/fixtures/capability-security/v1/cases.json`](../wit/fixtures/capability-security/v1/cases.json) contains host setup, explicit approvals, malicious operations and observable expectations. Build runnable packages with:

```sh
python3 scripts/build_security_fixtures.py --out-dir /tmp/security-fixtures
scripts/test_security_fixtures.sh
```

The builder emits three unsigned probe packages, an invalid unknown-permission package and eight valid components/packages demanding forbidden imports. All use a test-only identity; never add them to the catalog, trust them for production, or load them with native authority. Fixture signing is deliberately omitted. Consumers must explicitly allow unsigned fixtures in an isolated test trust policy so signature rejection does not mask permission failures. Do not disable normal package validation.

For each case, create fresh host state from `setup` plus optional `initial_storage` (or `initial_storage_entries` empty values under keys `entry-0`, `entry-1`, etc.), approve only the named profile, and bind the invocation to provider `fixture` / account `account-a`. Load the named package and invoke `health-probe.probe("fixture", JSON(operation))`. The guest deliberately attempts the operation regardless of approval. It exports the complete API-v1 world for typed host compatibility; exports other than the manifest-declared health probe return `permission_denied` without host calls. `detail-code` carries probe output; `http` reports response status, body byte count and truncation. The host tests, not the guest, assert `expect` against returned values, captured transport attempts, storage snapshots, logs, traces and client-visible errors. Inspect all guest-visible result/error fields for the setup secret. The response transport must not echo the injected credential.

Use mock DNS and HTTP behind the real host authorization boundary. Default DNS resolves fixture hosts to a public address without contacting the Internet; `dns` overrides resolution, `redirect` replaces the first response with a 302, and normal responses contain `http_response_bytes` bytes. `credential_injected` is observed only in the host transport. `revoked_credential` marks the selected credential unusable before invocation. Bind the clock to `now_unix_millis`. Preseed the other plugin's `shared` key to test isolation. Seed `other_account` with the same fixture credential, but do not authorize it for this invocation; missing account data must not mask account-scope denial. `deny` permits package/load rejection or a denied call, except request-budget tests require the first two approved attempts. No unauthorized mutation is allowed. Alternate outcomes such as `deny-or-return-redirect` are listed explicitly; stricter hosts should run a compatible isolated profile for positive boundary cases.

Each ambient package retains the valid probe export and must be rejected for its authority-bearing import. Each probe selects its own minimal world compiled from [pinned upstream WASI WIT](../capability-security-conformance/wit/README.md), preserving real signatures and cross-interface resource aliases without importing unrelated capabilities. They attempt `descriptor.open-at`, `preopens.get-directories`, `tcp-create-socket.create-tcp-socket`, outgoing HTTP `handle`, environment reads, and randomness. The process/shell and system-credential probes use explicitly non-contract `kinetix:ambient` operations. `ambient_imports` names the required function and the JSON `operation` for invoking the probe. Type-only and empty instance imports are not ambient-denial evidence. The invalid package must be rejected for its unknown permission. Missing authority-bearing imports must never be filled with permissive WASI or trap shims that falsely report successful authorization.

Local CI validates manifest/package structure and confirms regular probes reach their host calls. For ambient probes it asserts the exact compiled non-contract import set (including type dependencies), verifies the callable import, accepts an inert type-only control, rejects linking when only the named operation is withheld, and invokes each probe through test-only dependency shims until that exact operation traps. It also rejects ambient components when only the base probe's contract imports are linked. **It does not test Kinetix enforcement.** Consumers must execute the expectation vectors against their real host. Run the same vectors for every future JS/TS-to-WASM or other runtime; runtime initialization cannot add authority. Such runtimes also depend on the authoring/tooling and external compatibility contracts tracked in #70 and #71.
